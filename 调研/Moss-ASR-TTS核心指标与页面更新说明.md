# Moss ASR / TTS 核心指标与页面更新说明

- 日期：2026-09-08
- 文档状态：已按最终 7 类指标更新
- 页面实施状态：**已完成（第 7 版已按需求—实现复核修正）**
- 开始时间：2026-09-08
实施范围：用量明细7、请求日志7、服务质量7；保留 1–6 版作为历史对照。

## 1. 本次决策

客户侧只采用以下 7 类核心指标/能力：

1. 请求/调用次数；
2. TTS 计费字符；
3. ASR 计费音频时长；
4. 积分/资源包余量；
5. 并发峰值与上限；
6. 请求日志、request/trace ID；
7. 模型/API Key/用户筛选。

本次不作为客户侧核心范围：请求成功率、错误数/错误码聚合、时延均值或 P95/P99、TTS 首包时延、ASR 完成转写时延、当前并发、QPS/RPM、限流/429 事件统计。

这里的“不作为核心范围”是指不建设对应的汇总卡片、趋势图或告警。请求日志为解释单次请求仍可保留状态码、错误信息、单请求耗时和时间戳等基础字段，但它们不升级为客户看板指标。

## 2. 页面范围与命名建议

### 2.1 当前结构

**费用中心**

- 用量明细

**调用日志**

- 请求日志
- 服务质量

### 2.2 建议结构

**费用中心**

- 用量明细

**API 监控**（原“调用日志”）

- 请求日志
- 并发监控（原“服务质量”）

建议改名，理由如下：

- “调用日志”无法自然包含聚合型并发看板，“API 监控”可以同时覆盖请求日志和并发监控。
- 最终范围不含成功率、错误率和时延等服务质量指标，原“服务质量”页只承担并发容量查询，改为“并发监控”更准确。
- 不新增页面，只调整两个导航名称和三个现有子页面内的内容。

若本期不改导航，可继续使用旧名称，但“服务质量”页标题或说明必须明确：本页仅展示客户峰值并发及其生效上限，不代表 SLA 或完整服务质量。

## 3. 核心指标定义与页面归属

| 核心指标/能力 | 产品定义 | 主页面 | 辅助页面 | 展示建议 |
|---|---|---|---|---|
| 请求次数 | Moss 网关实际接收的 HTTP 请求、WebSocket 会话建立或异步任务提交次数；查询任务接口是否计入必须单独说明 | 请求日志 | 用量明细 | 请求日志按明细计数；用量明细只作计费调用次数的对照 |
| 计费调用次数 | 产生有效 MeterEvent、被计入计费或资源包扣减的调用次数；可能与请求次数不同 | 用量明细 | 请求日志 | 页面标签写“计费调用次数”，不要只写含混的“调用量” |
| TTS 计费字符 | 按当前客户生效计费规则进入计量的字符数 | 用量明细 | 请求日志 | 展示计费字符及其统计口径；厂商若按 bytes 计量，由内部完成换算或映射，客户页不展示 bytes |
| ASR 计费音频时长 | 按当前客户生效规则进入计量的有效输入音频时长 | 用量明细 | 请求日志 | 显示秒/分钟/小时及最小计费单位、进位规则 |
| 积分/资源包余量 | 当前企业账户积分或资源包剩余可用额度 | 用量明细 | — | 标注余额类型、有效期、更新时间和数据延迟；不使用 Credits 作为客户侧名称 |
| 并发峰值 | 所选时间窗口内任一统计点的最大并发值 | 并发监控 | 请求日志 | 显示 `窗口峰值 / 当时生效上限`、峰值时间和统计粒度 |
| 并发上限 | Moss 对当前企业、模型和调用模式实际生效的客户权益 | 并发监控 | — | 只显示客户生效上限，不显示供应商账号总配额 |
| request/trace ID | 可唯一定位一次 Moss 请求及其上下游链路的稳定标识 | 请求日志 | 用量明细 | 支持复制和精确搜索；若两个 ID 含义不同则分列 |
| 筛选维度 | 模型、API Key、用户 | 三个子页面 | — | 使用相同对象 ID、选项名称和空值规则；页面只开放适用维度 |

说明：

- “请求/调用次数”是一个核心类别，但页面上必须区分“请求次数”和“计费调用次数”。前者回答系统收到多少请求，后者回答产生多少次计量，两者不能为了数字一致而合并。
- 时间范围是三个页面的通用查询控件，不计入第 7 类业务筛选维度。
- “并发峰值与上限”只包含窗口峰值和对应的生效上限，不包含当前并发、剩余并发或利用率。

## 4. 各子页面需要更新的点

### 4.1 费用中心 → 用量明细

页面任务：回答“调用了多少、计费量是多少、还剩多少”。

保留或新增：

- 首屏摘要：请求次数、计费调用次数、TTS 计费字符、ASR 计费音频时长、积分/资源包余量；请求次数只作为计费调用的对照；
- 趋势：计费调用次数、TTS 计费字符、ASR 计费音频时长；
- 明细：模型、API Key、用户、计费调用次数、计费单位、计费量；
- 筛选：时间、模型、API Key、用户；
- 口径说明：计费单位、最小计费量、进位、失败/取消/重试、流式和异步任务的计数规则；
- 可从 MeterEvent 或 request ID 跳到请求日志核对。

需要移除：

- TTS bytes、Credits 等非最终客户侧名称；
- 应用筛选及应用归因列；
- 当前并发、RPM/QPS 当前值、峰值、上限和趋势；
- 429/限流统计与原因分布；
- 成功率、时延及其他运行质量指标；
- 上游厂商、上游账号、采购配额和内部路由维度。

并发峰值与上限移至“并发监控”，避免计费事实和容量权益混在一页。

### 4.2 API 监控 → 请求日志

页面任务：回答“某一次请求是什么、由谁调用、能否追踪”。

保留或新增：

- 列表主键：request ID；有独立 trace ID 时分列展示；
- 基础字段：时间、请求方式/模式、模型、API Key、用户；
- 诊断字段：响应状态码、错误信息、单请求耗时、计费量、MeterEvent ID；这些是单请求属性，不作为汇总 KPI；
- 搜索：request ID、trace ID；
- 筛选：时间、模型、API Key、用户；
- 操作：复制 ID、打开详情、跳到同一筛选范围的用量明细。

需要移除：

- 应用筛选及应用字段；
- 请求成功率、P95/P99、错误率、429 次数等 KPI 卡；
- 错误原因聚合图、429 热力图、RPM/并发趋势；
- 上游厂商容量与其他租户信息。

请求日志仍可按状态码或错误文本查找单次请求，但不把错误聚合升级为本次核心指标。

### 4.3 API 监控 → 并发监控（原“服务质量”）

页面任务：回答“所选时间范围内的并发峰值是多少，是否接近当时的生效上限”。

保留或新增：

- 所选时间窗口并发峰值；
- 峰值时刻及峰值时对应的生效上限；
- 峰值并发趋势，基准线使用历史当时生效上限；
- 时间、模型、API Key、用户筛选；
- 数据更新时间与统计粒度；
- 从峰值时间点下钻到对应请求日志。

需要移除：

- 当前并发、剩余并发、并发利用率；
- 应用筛选；
- 请求成功率、错误数/错误码分布；
- 平均时延、P50/P95/P99；
- TTS 首包时延、ASR 完成转写时延；
- RPM/QPS 当前值、峰值、上限和趋势；
- 429/限流事件统计和原因下钻；
- 上游供应商配额、水位和内部队列信息。

## 5. 跨页面规则

### 5.1 统一筛选

- 模型为第一业务维度，API Key、用户作为归因维度，时间范围作为统计窗口；
- 同一筛选项必须使用稳定 ID，不依赖显示名称关联；
- 用户维度只使用可信调用身份或 API Key 归属，不从前端填写姓名推断；
- 角色无权查看企业全量时，只展示本人或授权范围，不保留不可用的“全部用户”假选项；
- 从一个页面下钻到另一个页面时，保留时间、模型、API Key 和用户上下文。

### 5.2 数据口径与延迟

- 请求日志使用请求发生时间；计费用量使用 MeterEvent 发生/入账时间；两者不同必须明示；
- 并发峰值必须显示时间窗口、峰值时间和统计粒度；并发上限采用峰值发生时实际生效的历史值；
- 积分/资源包余量若由厂商或账务系统延迟同步，必须显示“数据截至时间”，不能伪装成实时；
- 空数据、采集未覆盖、权限不可见和数据加载失败使用不同状态。

### 5.3 客户与内部边界

- 客户只看到 Moss 对其企业、模型和调用模式生效的并发上限；
- 不展示供应商名称、供应商账号总配额、其他租户占用、采购成本、内部路由和队列阈值；
- 上游容量问题仍需在内部监控和请求证据中记录，但不扩展为本次客户核心指标。
