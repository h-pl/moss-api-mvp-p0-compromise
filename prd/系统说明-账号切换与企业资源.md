# 系统说明：身份、数据归属与一致性

更新：2026-09-11。业务规则见[主PRD](./PRD-管理和组织模块.md)7.1、7.6–7.8和7.10。本文定义研发需要保证的数据边界，不指定未经评审的HTTP路径或存储技术。

## 1. 可信上下文与实体

| 实体 | 最小关联与约束 |
|---|---|
| 登录主体 | 稳定用户ID、已验证手机号；URL和前端角色参数不授予权限 |
| 企业成员关系 | 企业ID、用户ID、成员ID、角色、状态、关系版本；Owner由模思运营按销售订单配置 |
| 模型策略 | 企业×模型的企业上限、成员授权、可空成员上限、配置版本；null与未授权分别存储 |
| 邀请 | 企业、受邀手机号、角色、模型配置、邀请标识、成员关系版本、created_at、expires_at、投递状态 |
| 企业Key | 稳定Key ID、企业、用户、成员关系版本、状态、名称和掩码；Secret仅创建时一次性交付 |
| 计量记录 | 稳定企业/用户/成员关系/Key/模型标识、发生时间、单位、生效规则版本和费用结果 |

每次读写和下载都根据可信主体与正常成员关系校验权限。切换身份后隔离缓存和请求上下文；旧响应不得覆盖新身份页面。成员姓名、手机号掩码、列表索引不能作为关联键。

## 2. 成员事务

邀请写入原子校验操作者、角色范围、手机号重复、有效席位和单模型上限，保存邀请及配置；不计算成员上限总和。席位只统计正常成员及服务端当前时间早于expires_at的有效待接受邀请，不能依赖异步过期任务及时更新状态。

接受操作重验手机号、邀请期限、撤销状态和关系版本，幂等地将待接受转为正常，不能重复占席位。短信投递状态独立于邀请状态，重试复用有效邀请；1天（24小时）邀请凭证与按次生成的短期SSO状态分离。完整登录分支和文案见主PRD7.6.4。

编辑按当前成员/配置版本整笔校验和提交。移除撤销企业访问、未接受邀请并永久失效该关系的企业Key，同时保留个人账号、个人Key及历史账本。同手机号重邀创建新关系版本，旧Key、邀请和写请求不能恢复权限或绑定到新关系。

## 3. 并发执行

配置含义以主PRD7.7.1为准：授权且null不单独设限；显式上限限制本人；未授权不可调用。企业×模型是共享池，成员配置不占用容量。

网关使用同一原子准入过程验证Key、正常成员关系、模型授权及当前企业/成员策略，然后增加企业与成员实际占用。多个Key不得各自获得独立成员额度。每次占用有可幂等结束的请求标识；完成、失败、取消和超时均释放实际占用，异常中断需有回收机制，重复结束不重复扣减。

企业或成员并发达到上限时直接拒绝新请求，不排队，由调用方稍后重试。缩容、停用Key、取消授权或移除立即约束后续新请求；已接纳请求允许继续完成，不因策略变化主动中断，在完成、失败、主动取消或超时前持续计数，不能通过删除配置提前清零。企业缩容保留成员显式配置和历史峰值，当前生效上限取企业上限与显式成员上限的较小值；null随企业上限变化。具体错误码和重试指引由网关研发落实，见主PRD Q-05。

## 4. Key写入与撤权

创建、普通停用和启用重新检查本人归属、当前关系与动作前态；创建还检查授权和50个额度。普通停用占额度，成员移除产生的永久失效Key不占额度且不可再启用。签发必须幂等，失败不得产生无归属或重复Key；列表、日志、埋点和持久缓存不得含生产Secret。

成员状态与Key撤权需协同生效，网关不得因前端旧缓存继续接受新请求。已接纳请求允许完成；具体状态传播时限由接口评审确定并提供可验证指标。

## 5. 计量快照与查询

账本按稳定标识归属，模型授权收回或成员移除不删除历史计量。实际价格、折扣、计费单位、舍入和生效时间从销售订单对应的运营配置获取，历史结果保留当时规则版本。积分余量是独立权益快照，不能由本月消费倒算。

查询支持当前月及此前11个月，按Asia/Shanghai月账期计算；范围外请求明确拒绝，不将页面查询期限作为底层账务记录删除期限。底层保存及归档期限由研发与财务落实。

页面、趋势、分页合计、账单与CSV在相同账期、权限范围和快照下保持一致；合计不取当前页。打印使用完整企业账期并按模型汇总，CSV使用完整授权账期并按模型×用户×Key汇总，具体字段和时间边界见主PRD7.4–7.5。下载生成与获取均须重新鉴权。

## 6. 失败契约

写入必须具有幂等与版本检查；失败保留输入，版本冲突提示刷新，不先展示成功。关系失效立即阻止旧上下文继续操作。未知、未覆盖、加载失败与真实零分别表达。接口能力及字段见主PRD7.10，未定参数见文末8.3；实现落点和原型限制见[联调说明](./实现与联调说明.md)。
