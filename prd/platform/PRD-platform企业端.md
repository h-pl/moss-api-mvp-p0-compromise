# Platform 企业端 PRD

版本：MVP P0 妥协版 v1.0.0，2026-09-14。当前工作区唯一有效企业端需求；本目录取代原多角色企业控制台 PRD。以本轮用户确认决策为准。

私有仓库：[moss-api-mvp-p0-compromise](https://github.com/h-pl/moss-api-mvp-p0-compromise)；在线原型：[Moss API](https://moss-api-mvp-p0-compromise.vercel.app)。`main` 已关联 Vercel 自动部署。

对比原 MVP 的完整变更与版本基线见 [版本变更说明](变更说明-MVP至妥协版-20260914.md)。本 PRD 正文描述当前有效规则，历史需求不自动沿用。

## 1. 目标与边界

沿用 platform.mosi.cn 的界面，将原企业能力收敛到企业 Owner 管理 API Key。没有邀请、子租户、席位、Admin、Developer 或成员列表。仅迁移功能，不迁移历史原型的角色数据。

运营后台沿用，运营将已有 C 端账户配置为企业 Owner，设置企业授权模型和每模型并发上限。本次不新增运营配置页。Owner 在账户菜单切换个人／企业，企业端只能查看运营配置，不能自行扩充企业权益。

平台首页、Playground、API Docs 不复刻，侧栏原站链接保留。交付 API Keys、用量与积分、计费标准、积分获取弹窗、身份切换及个人信息入口。原型不发起实际充值、真实 API 调用或生产密钥变更。

## 2. 身份和资源

个人 Key 与企业 Key 分开管理、分别统计并扣减对应积分。个人创建与编辑 Key 支持勾选可调用模型，默认全选、至少选择一个；桌面采用两列模型卡片，窄屏单列。个人 Key 列表在密钥后显示“授权模型”列，逐行列出已选模型名称。个人不展示或编辑 Key 并发路数，仍遵循平台账户限制。保存、重新编辑及刷新后保留模型范围，变更不改写历史用量。企业 Owner 统一创建并持有企业 Key，自己复制给使用者；使用者不需要加入平台或创建企业成员关系。备注可以描述用途或团队，但不是受邀人员身份。

同企业同模型共享一个并发池。例：企业模型上限 100，两把 Key 可分别设 80，同时实际调用总和仍不能超过 100。Key 单项上限不得超过企业上限；各 Key 上限之和不受此约束。请求需同时满足企业池和 Key 上限。超限新请求直接拒绝，不排队；已经接纳的请求可完成，其占用在结束时释放。

运营撤销模型或调低企业上限时，服务端应按当前企业权益和 Key 配置共同判断有效权限；历史计量与峰值不改写。具体配置服务接口和网关原子计数需真实后端接入验收，原型没有运营修改入口。

## 3. API Keys

原站布局：API Key 标题与数量、右侧创建按钮、一次性展示提示、搜索和状态筛选、Key 表格。企业端增加可展开的企业授权模型区、Key 授权模型与并发列、备注及编辑/用量入口。

| 字段 | 规则 |
| --- | --- |
| 名称 | 必填，去首尾空格后 1–50 字符；沿用原站名称概念，不与备注合并 |
| 模型 | 至少一个；企业仅选企业已授权模型，个人选择当前账户可用模型；新建默认全选，编辑恢复已保存范围 |
| 每模型 Key 上限 | 仅企业提供，必填整数，1 至企业该模型上限，默认填企业上限；取消勾选移除授权并禁用输入。个人无此输入，不代表无限并发 |
| 备注 | 可选，最多 200 字符，用于描述团队、项目或用途 |
| Key 数量 | 沿用平台每身份最多 50 个未删除 Key；停用仍计入，删除释放创建名额 |
| 完整密钥 | 创建成功仅展示一次，可当场复制或手动选中复制；关闭后不可查看/复制；列表仅掩码 |

个人列表列序：名称、密钥、授权模型、备注、创建时间、状态、操作；企业对应列名为“授权模型 / 并发上限”。个人模型列逐行显示名称，不显示路数。个人创建/编辑为两列勾选卡片，600px 及以下单列；企业保持每模型复选框与并发输入的行布局。

创建失败保留表单，不展示成功或密钥。创建成功后显示持续存在的密钥结果弹窗，用户保存后关闭。编辑可调整名称、授权及备注；企业另可调整并发，不改变 Key 字符串。关闭/取消不保存修改。失去完整 Key 时应创建新 Key。

停用/恢复弹出影响确认。删除永久撤销 Key，不可恢复，并保留历史用量的稳定 Key ID。启停、删除、授权修改不重写历史用量。搜索名称、备注或尾号；状态筛选、分页和总数一致。Key 行用量入口直接选择对应 Key。

## 4. 用量与积分

沿用原站布局：账户积分双卡 → 筛选 → 消耗积分/计费请求次数双卡 → 企业并发区（个人跳过） → 用量概览/请求明细页签 → 原有趋势与表格。并发为新增独立区，其余模块保持原有视觉结构。

筛选顺序固定：**时间范围 ｜ 全部模型 ｜ 全部 Key**。模型与 Key 可独立选择，结果取交集。筛选区没有“重置”操作。支持近 7 天、本月及自定义日期；北京时间自然日，起止日期均包含。近 7 天截至昨日；本月从当前月份 1 日至昨日，每月 1 日显示“本月暂无已同步数据”，不回退查询上个月。自定义截止日期不得晚于昨日，开始不得晚于结束。已删除 Key 保留在历史筛选中并标记状态。

积分与请求数据按日同步，页面说明次日同步口径，日期范围只包含已完成日期。月初尚无完整日期时显示待同步空态，两个导出入口均不可用。账户余额与累计消耗属于账户整体，不被筛选改变；所选范围的消耗、计费请求、图表、表格及导出同源。时间预设、自定义起止日期、模型、Key、页签、页码和每页条数保存到 URL，刷新与前进/后退恢复对应状态；Key 行下钻入口携带稳定 Key ID。切换个人/企业空间清除原筛选，URL 中不属于当前身份的 Key 不生效，URL 不授予账户权限。

### 4.1 并发

并发峰值卡片仅在企业空间展示，个人空间用量页不展示此卡片。窗口固定滚动近 24 小时，不随账单时间改变；按分钟更新窗口时钟并展示更新时间。原型基于固定请求 fixture 重算，生产需接真实并发接口。

| 模型 | Key | 展示 |
| --- | --- | --- |
| 全部 | 全部 | 各模型企业峰值 / 企业上限 |
| 指定 | 全部 | 指定模型企业峰值 / 企业上限 |
| 指定 | 指定 | 此 Key 在该模型上的峰值 / Key 上限 |
| 全部 | 指定 | 此 Key 各模型峰值 / 对应 Key 上限 |

企业峰值计算所有 Key 同时在途请求，不是各 Key 历史峰值相加。多个模型也不合成一个峰值。当前卡片显示统计更新时间；峰值发生时刻由并发数据保留，未在卡片额外展示。停用/删除 Key 的历史峰值保留，显示当前状态；模型撤权显示未授权，历史峰值高于新上限不截断。

### 4.2 概览与请求

保留按模型积分堆叠趋势，桌面图例位于右上角，底部日期积分说明不显示。模型用量概览为白底无色块，保留模型、计费请求次数、计费用量、消耗积分、折后金额估算、查看明细及汇总行。计费请求次数仅统计实际扣除积分的请求（积分大于 0）。用量概览、请求明细、两种 CSV 和账单预览均只包含这些已计费请求，不承诺可在此查看全部调用日志。ASR 用量换算小时，TTS 使用字符，汇总分别列出。折后金额估算暂按基础积分包 1 积分＝0.05 元，消耗积分已含模型折扣，不再次折扣；用户确认充值规则统一，企业差异仅在消耗模型折扣；金额为按基础积分包比例估算，不代表充值优惠包的实付成本。模型行可下钻到请求明细。请求明细按请求一行，字段为时间、请求 ID、API Key、接口、模型、状态、积分；点击请求 ID 展示计量详情。

模型用量不同单位不直接相加为单一用量总数；积分和请求次数可以汇总。失败请求是否计费来自实际计量数据，不能仅由 HTTP 状态推导。

### 4.3 导出

页签行右侧放“导出账单”“导出明细”。弹窗标题分别为“账单预览”“导出明细”；二者共用账户名称、北京时间起止日期、模型和 API Key 范围的头部形式。不显示重复的按模型汇总说明或“可在打印窗口另存为 PDF”提示。账单预览六项摘要为账单周期、计费模型、计费请求次数、消耗积分、折后金额估算、积分换算率；导出明细使用四项摘要。

| 类型 | 粒度与格式 | 关键字段 |
| --- | --- | --- |
| 账单预览 | 按模型汇总；“打印账单”调用浏览器打印，可保存 PDF | 计费模型及 TTS/ASR 标签、计费规则/折扣、计费请求次数、计费用量、消耗积分、折后金额估算及合计 |
| 导出明细（默认） | 按模型 → Key 汇总；CSV | 账户、起止日期、计费模型、Key ID、API Key 名称、密钥掩码、备注、计费请求次数、计费用量/单位、消耗积分、折后金额估算 |
| 逐请求明细 | 每个已计费请求一行；CSV | 账户、起止日期、请求 ID/北京时间、计费模型、Key ID/名称/掩码/备注、接口、状态、计费用量/单位、消耗积分、结算单价/单位、模型折扣、折后金额估算 |

导出明细弹窗摘要顺序为：计费请求次数 → 消耗积分 → 折后金额估算 → 导出记录。汇总预览表显示计费模型及类型标签、API Key、计费请求次数、计费用量、消耗积分、折后金额估算；不增加计费规则列。Key ID 保留在 CSV，不展示完整密钥，不导出“计费版本”或非计费口径的“请求次数”。计费版本仍留在内部请求费率快照中供追溯。

导出包含当前筛选范围所有已计费记录，不受页面分页限制；无数据或无效自定义日期时两个导出入口禁用。CSV 支持中文、引号和换行，用户填写内容做公式注入转义。积分按整数最小单位累计再格式化。两种 CSV 的“折后金额估算（元）”均保留 **4 位小数**，用户汇总这些值后统一保留 **2 位小数**；页面和 PDF 中的金额保留 2 位。不能先将逐请求金额舍入到 2 位再求和，否则会产生累计舍入差异。

账单预览保留模型价格和折扣；日期与筛选遵循页面选择。打印采用 A4 横向，正文与预览共享内容，打印时移除弹窗操作和背景页面；实际输出分页需在目标浏览器的打印预览中验收。

## 5. 计费标准与积分获取

企业按模型分别配置折扣，由运营维护，Owner 只读。企业价格为标准模型积分单价乘模型折扣，最低扣费沿用模型配置。个人账户使用标准价格，不继承企业折扣。新请求记录生效的单价、折扣、最低扣费及计费版本；历史账单按请求快照计算，不能由当前价格倒算。原型使用固定合同样本，不代表真实报价。

积分获取复刻双页签：个人充值展示原站截图积分包、选择状态、应付金额、有效期说明和商务定制。企业支付展示认证提示、收款单位、开户银行、银行账号；Owner 企业合同和付款信息可展开。商务定制仅在个人充值页签出现。真实收款账户未提供，界面显示待运营提供，不制造银行账户或支付二维码。支付接口未接入，点击支付展示明确状态并可转原平台继续。

个人身份的企业支付为未认证状态，提供原平台认证入口；当前 Owner 样本展示已认证状态。认证并非 Owner 权限的替代条件，生产状态应由后端独立返回。

## 6. 上线服务依赖

| 服务 | 需提供 |
| --- | --- |
| 身份/运营配置 | 可信 Owner 身份、企业模型与上限、个人/企业隔离；不能信任前端参数授予 Owner |
| Key 服务 | 服务端生成一次性明文，存储校验材料与掩码，真实鉴权、启停/撤销和策略版本 |
| 网关 | 企业×模型共享并发、Key×模型限流、原子接纳及幂等释放、配置变更后的生效策略 |
| 合同与支付 | 企业逐模型价格、折扣、历史价格版本、认证状态、合同/付款信息、真实收款账户、订单与到账回调 |
| 计量与账务 | 稳定模型/Key/request 标识、实际用量及积分、统一北京时间边界、已同步水位 |
| 并发监测 | 真实近 24h 峰值、时刻及更新时间；不以用量日统计替代并发事件 |
| 导出 | 按相同鉴权和筛选生成完整数据；大数据量需异步导出服务 |

当前版本为前端可交互原型；这些生产服务尚未接入。真实金额、模型合同参数和计费费率以运营/计费服务为准，不能使用 fixture 作为生产配置。


## 7. 界面与交互交付约定

沿用 Moss Platform 品牌、Sora/MiSans 字体、原站导航及真实 Reka UI 交互组件；不沿用旧 MVP 的四页侧栏和演示角色选择。企业授权区保留折叠/展开动画，并发进度条在模型或 Key 切换时过渡，遵循 reduced-motion；统计数字直接更新，不增加滚动计数动画。

账单预览与导出明细保留浅灰摘要卡片，数据表使用白底、横向分隔线，不加外围卡片边框。两弹窗表头统一为 #777；模型名称附 TTS/ASR 标签；数值表头与内容右对齐。模型用量概览和请求明细统一使用行分隔线。账单行高和留白压缩以便常见桌面完整浏览，内容较多或窄屏时在容器内滚动，不承诺任何浏览器和数据量都只占一页 PDF。

计费标准按 TTS/ASR 分组，两表使用相同列宽；企业显示标准价、企业折扣、企业价及最低扣费。保留原平台积分包卡片和商务定制布局。黑色主操作共享默认/悬停样式，不为打印或下载按钮单独使用另一种悬停色。

帮助文案按所在模块解释当前数据：用量说明为“仅展示已计费请求，消耗积分已包含模型折扣”；企业峰值说明只描述近 24 小时峰值与当前上限；共享池及 Key 不预留资源的规则集中在企业授权区，不在各处重复。个人用量筛选提示不提并发。个人信息页保持原平台基本信息及认证呈现，本轮不修改认证对象或状态。

## 8. 关键验收场景

| 场景 | 预期结果 |
| --- | --- |
| 企业创建/编辑 Key | 仅企业授权模型；至少一个；每模型 1 至企业上限整数；各 Key 上限之和可超过共享池 |
| 个人创建/编辑 Key | 两列模型选择、手机单列；无并发输入；空选不可保存；列表授权列与保存、刷新结果一致 |
| 个人/企业切换 | Key、积分和用量隔离；清理筛选/弹窗旧上下文；个人无并发卡片，企业恢复显示 |
| 从 Key 查看用量后刷新 | URL 恢复对应 Key、模型、日期、页签和分页；外身份 Key 无效 |
| 每月 1 日选本月 | “本月暂无已同步数据”，不回退上月；导出按钮禁用 |
| 对账 | 相同范围内概览、请求明细、PDF 预览、两种 CSV 的积分一致；CSV 金额 4 位相加后舍入 2 位，与账单一致 |
| CSV 字段 | 保留 Key ID；不导出计费版本或额外的非计费请求次数；不导出完整密钥 |
| 导出范围 | 采用所选时间/模型/Key 的全部已计费记录，不受表格分页影响 |
| Key 生命周期 | Secret 仅创建时展示；取消不保存；启停/删除影响后续调用，不修改历史计量与归因 |
| 交互和生产边界 | 弹窗、键盘和窄屏可操作；真实登录、支付、网关及后端计费未接入；PDF 实际分页单独验收 |
