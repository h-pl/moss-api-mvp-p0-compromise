# 原 MVP → Moss API MVP P0 妥协版：完整变更说明

版本：v1.0.0；日期：2026-09-14。
Tag：`moss-api-mvp-p0-compromise-v1.0.0-20260914`（带注释的版本标签，指向本说明与当前代码一并提交的版本）。

## 1. 对比基线与适用范围

原 MVP 基线是 2026-09-11 研发评审稿及旧工作区提交 `eb053ec061f22a20a215e2a30068c8f5b8cab089`，需求见 [原企业 MVP PRD](../PRD-管理和组织模块.md)。它在更早的四页定稿上保留 Owner/Admin/Developer、成员授权、邀请与共享并发，不能把更早“移除用户”的过程版本当作最终旧基线。

当前版本以 [Platform 企业端 PRD](PRD-platform企业端.md) 为准；代码集中在 `app/platform/`。新仓库首个提交 `ff9ca62` 已包含相对旧 MVP 的大部分迁移，不代表“原 MVP”。后续 `1ba4073` 是本次整理前最新应用代码，包含个人模型选择及列表授权列。本 tag 同时纳入完整文档整理。

旧工作区与新仓库不是同一条 Git 历史；本说明按旧有效 PRD、保留源码、当前实现和本轮验收对比，不把新仓库的首次快照与旧仓库误作可直接按父子提交比较的关系。

## 2. 产品结构与权限变化

| 项目 | 原 MVP | 妥协版当前规则 |
| --- | --- | --- |
| 产品界面 | 独立企业控制台，管理/组织四页 | 沿用 Moss Platform 导航、品牌、字体和交互；在平台结构内扩展企业能力 |
| 主要入口 | API 密钥、费用概览、用量明细、企业与用户 | API Keys、用量与积分、计费标准；积分获取弹窗和个人信息入口 |
| 路由 | `?view=keys/billing3/usage3/enterprise` | `/app/api-keys`、`/app/usage`、`/app/pricing`、`/app/profile`；默认进入 API Keys |
| 企业角色 | Owner/Admin/Developer；按角色访问和配置 | 仅企业 Owner 管理企业 Key，无企业成员列表、Admin/Developer 或角色选择器 |
| 授权对象 | Owner/Admin 为成员配置模型；成员创建本人 Key | Owner 直接为每把企业 Key 配置模型与并发上限 |
| 企业开通 | 运营按销售订单配置 Owner/企业权益 | 保留既有运营流程；本次不新增运营后台，前台只读企业授权 |
| 邀请与席位 | 成员邀请、接受/失效、席位及移除生命周期 | 退出当前范围；没有邀请、成员关系或子租户操作 |
| Key 使用者 | 需要企业成员身份，管理本人 Key | Owner 创建并交付 Key；使用者无需加入企业。备注仅说明团队/用途 |
| 企业并发层级 | 企业 → 成员 → 该成员多把 Key，共享成员限额 | 企业×模型共享池 + 每 Key×模型上限；无成员限额中间层 |
| 上限语义 | 成员上限可留空继承企业资源 | 企业 Key 每模型须为 1 至企业上限的整数，默认企业上限；各 Key 上限总和可超过企业池，不预留资源 |
| 个人与企业 | 个人服务主要跳转 C 端；企业为四页 | 当前页内切换个人/企业；Key、积分、用量隔离，个人标准价、企业逐模型折扣 |
| 外部入口 | 旧企业原型的一组模块/候选 | 平台首页、Playground、API Docs、开发者社区保留原站外链；不宣称复刻外链功能 |

超限新请求直接拒绝、不排队，已接纳请求可完成；历史计量不随授权、启停或移除变化。这些原则沿用，网关原子计数仍需生产服务接入。

## 3. API Key 完整改动

- 企业列表增加可折叠的“企业授权模型”区，显示六模型共享并发额度；统一列宽，模型与路数对齐，长名称可读，备注可换行、时间和操作避免挤压。
- 企业创建/编辑包含名称、模型勾选、每模型并发上限和备注；默认全部已授权模型及对应企业上限，至少选择一个；取消模型会删除其策略并禁用输入，非法/越界上限阻止保存。
- 个人创建/编辑由固定“全部 API”改为可选模型范围。默认全选、至少一个；桌面两列模型卡片、手机单列；不提供并发路数输入，仍遵循平台限制。保存后重新编辑、刷新保持选择，不自动补回取消的模型。
- 个人列表新增“授权模型”列，位于密钥后，逐行显示已选模型；企业同一位置仍为“授权模型 / 并发上限”。
- 创建成功使用专用密钥结果弹窗和成功提示；横向密钥框、复制反馈、一次性展示提示。完整值只保留当前内存，不写入浏览器存储，关闭后无法再次取回。
- 编辑不更换 Key；取消不保存。启停/删除有影响确认，删除保留历史归因。各身份最多 50 个未删除 Key，停用计数、删除释放数量。
- 搜索名称、备注或尾号；状态筛选和分页共用结果。Key 行下钻携带稳定 Key ID 到用量 URL，个人入口不再提示查看并发。

## 4. 用量、并发与数据口径

| 项目 | 当前交付 |
| --- | --- |
| 页面组织 | 账户积分双卡、时间/模型/Key 筛选、范围统计双卡、企业并发区、用量概览/请求明细；不再分离原费用概览和用量明细两页 |
| 归因维度 | 删除用户维度；账单按模型，明细按模型→Key 或逐请求 |
| 请求口径 | 概览、请求明细、账单和两种 CSV 均仅含实际扣分请求；统一称“计费请求次数”。不声称全部调用日志可在请求明细查看 |
| 时间 | 北京时间自然日；近 7 天、本月、自定义，截至昨日，次日同步；自定义不可选择未来或结束早于开始 |
| 月初修复 | 本月始终从当前月 1 日开始；每月 1 日显示“本月暂无已同步数据”，不返回上个月；无数据时不可导出 |
| URL 恢复 | 时间、自定义日期、模型、Key、页签、页码、每页条数写入 URL；刷新和前进/后退恢复；非法参数或外身份 Key 安全回退 |
| 身份切换 | 清理原身份筛选和弹窗上下文；个人/企业存储和查询隔离，不以 URL 授予权限 |
| 企业峰值 | 固定滚动近 24 小时，与账单日期独立；按同模型同时在途请求计算，不累加各 Key 独立峰值；展示峰值/当前上限及更新时间 |
| 个人峰值 | 个人用量页不展示并发峰值卡片，个人筛选帮助不再包含并发说明 |
| 历史状态 | 停用/删除或调低上限不改写历史；保留 Key 归因、未授权和历史峰值高于现上限等说明 |
| 积分/金额 | 积分已包含模型折扣；按 1 积分=0.05 元估算，不再应用一次折扣；金额不是优惠充值包的实付成本 |
| 用量单位 | TTS 字符、ASR 小时；合计分单位列出，不将字符与小时直接相加 |
| 图表与表格 | 按模型积分堆叠趋势，图例右上、悬浮显示日期和模型积分；模型概览保留用量、积分、金额、明细入口及合计；与请求表统一横向分隔线 |

原 MVP 已在 9 月 9 日移除独立调用日志模块，也已具备 PDF 打印能力；本版没有“首次删除全部日志”或“首次引入 PDF”的说法。此次区别是新增平台式已计费请求明细，并将导出范围改为当前筛选结果。

## 5. 账单与 CSV 定稿

- 原 MVP 按完整授权账期打印/导出，不受页面筛选缩小；妥协版采用当前时间、模型和 Key 筛选的全部已计费记录，仍不受分页影响。
- 页面入口为“导出账单”，弹窗名称统一“账单预览”，主操作“打印账单”；浏览器原生打印，可另存 PDF。替换本轮早期的账单 CSV 草案，导出明细仍为 CSV。
- 账单与导出明细头部统一：标题、账户、北京时间日期范围、模型/API Key 范围。移除重复的汇总说明、“可在打印窗口另存为 PDF”提示和用量表下重复换算说明。
- 两弹窗保留浅灰摘要卡，表格改为白底横线，不用外围卡片框；表头统一 #777，模型附 TTS/ASR 标签，数值及表头右对齐，主按钮默认/悬停颜色共用平台样式。
- 账单摘要六项：周期、计费模型、计费请求次数、消耗积分、折后金额估算、积分换算率。表格保留计费规则/折扣（划线标准价、折后价、折扣标签），行高与空白压缩，合计金额按汇总积分计算。
- 导出明细摘要顺序：计费请求次数 → 消耗积分 → 折后金额估算 → 导出记录。汇总预览显示模型、API Key、计费请求次数、计费用量、消耗积分、金额；不再增加重复的计费规则列。
- CSV 保留 Key ID、名称、掩码、备注等归因；逐请求另保留请求 ID/时间、结算单价及模型折扣。不导出完整 Key、计费版本或额外的非计费请求次数。计费版本保留在内部快照及请求详情以供追溯。
- 两种 CSV 金额均保留 4 位小数，累加后统一保留 2 位。修复原样本逐请求舍入后相加 ¥53.79、账单 ¥53.98 的差异；积分保持 1,079.56 不变。CSV 不逐行先舍入 2 位再求和。
- 打印样式为 A4 横向，隐藏导航/背景/操作，使用预览同一数据；六模型常见桌面布局已压缩。实际 PDF 文件分页仍待目标浏览器验收，不承诺所有记录量都一页。

## 6. 计费、充值与视觉交互

- 六个模型按 TTS/ASR 分组；标准价、企业折扣、企业价、最低扣费分别展示。两组使用相同列宽，避免上下错位；窄屏在宽表容器内横向滚动。
- 企业折扣按模型配置并写入请求费率快照；个人按标准价。充值套餐规则统一，企业差异在模型消费折扣，不重复对已折扣积分打折。
- 保留原 Platform 积分包及商务定制样式、字体、绿色角标和购买入口；积分获取弹窗为个人充值/企业支付双页签。企业支付不显示个人商务定制，合同和对公信息可展开。
- 个人信息页维持原平台基本信息和认证呈现；不改认证对象/状态，不将其与企业 Owner 资格合并。未填写真实收款资料时显示待提供，未接入支付时不伪造到账。
- 使用真正的 Reka UI 下拉、日期范围、页签、弹窗、开关、复选框和菜单，React 通过 Vue 岛接入。共享原站 Sora/MiSans 字体、品牌和中性色，不改为另一套通用后台主题。
- 企业授权区折叠/展开、并发进度条和趋势图有过渡，支持减少动态效果；数字直接刷新，不增加滚动计数动画。长模型名单行省略的区域提供完整名称，弹窗和宽表窄屏可滚动，关闭/提交与键盘焦点可达。
- 帮助文案删除“由运营配置”式内部口吻；共享池规则集中解释，峰值卡仅说明统计范围/当前上限；用量帮助为“仅展示已计费请求，消耗积分已包含模型折扣”。
