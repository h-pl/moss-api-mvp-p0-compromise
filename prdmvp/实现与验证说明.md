## 当前验证方法


并发表达统一（2026-09-09）：企业资源池两列、API凭证三列（保留积分），并发列分别显示近24h峰值/企业并发上限、近24h峰值/本人并发上限。CapacitySnapshot.currentLimit直接读取当前配置；历史峰值和发生时间不受配置修改影响，分母、状态及筛选会更新。页面底部仅显示数据更新于……，统计说明入口和长段解释移除。低于80%中性、80%至不足100%橙色、100%起红色；缺失峰值保留已知上限，不误判充足。

- node scripts/verify-mvp.mjs：角色隔离、用户/模型/Key归因、账期窗口、费率及聚合、打印导出、跳转和旧路由兼容。
- node scripts/verify-usage8.mjs：复用计量选择器的8组回归。
- node scripts/verify-v3.mjs：企业四页、个人身份、共同交互与文档28项契约检查。
- ESLint、TypeScript与Next生产构建；浏览器检查两页导航、用户到Key下钻、Developer权限、模型账单和窄屏表格。

前端fixture不能证明生产扣费、短信送达、网关撤销或服务端权限。必须接入真实身份、计量、账务、资源与下载权限后执行生产验收。不要将历史Mock复核金额作为当前费率下的固定期望值。


## 历史阶段：企业与用户：移除用户（2026-09-09）

历史迭代阶段仅修改 `enterprise2` 及共享MVP成员/Key状态；后续选定原2版并清理旧enterprise页面，正式路由与当前验收以下方清理记录为准。变更前基线为 `pre-user-removal-major-update-20260909`。

行内和详情操作改为“移除用户”，站内确认后从用户与配额、搜索、筛选、计数中隐藏，释放已加入/待接受占用席位。Owner不可移除本人或Owner，Admin只能管理Developer；提交时重验最新角色、状态和成员关系版本。

同一手机号通过“邀请用户”重新添加，沿用稳定用户ID与历史姓名，配置新的角色和模型权限，生成新版本待接受邀请。原型仍只生成邀请记录，不发送短信或模拟真实受邀人登录。真实邀请接受及网关撤权需后端接入。

内部保留已移除身份与Key元数据。企业Key写入永久失效标记，重新邀请后仍不能启用，永久失效的历史Key不占新关系的50个创建额度，个人Key不受影响。成员和Key以一个状态快照提交并持久化；旧已停用MVP记录迁移为已移除。费用与用量数据继续使用完整历史目录，账单行、用户/Key分组、CSV、账期打印、企业余额不因移除或重新邀请改变。

新增回归覆盖移除/重邀、待接受记录移除、重复邀请/席位限制、权限越界、旧弹窗版本、旧Key不可启用、缓存迁移、历史费用及用量逐行一致。浏览器检查邀请→移除→重新邀请，并核对列表和席位变化。

本轮验证：MVP回归29项、用量回归8项通过；变更代码ESLint无错误或警告；生产构建与TypeScript检查通过。浏览器完成邀请→移除→同手机号重新邀请→再次移除→重新载入，成员数与席位同步，临时验证用户已移除。


## 历史阶段：企业与用户：用户详情字段精简（2026-09-09）

查看用户时保留企业API Key只读列表，用于核对该用户使用情况和移除影响；列为名称/掩码、状态、最近调用，删除不存在的“有效期至”。模型明细仅列已授权项，顶部仍显示已授权/企业模型总数；无授权时显示明确空态。未授权模型继续在编辑与邀请表单供管理员选择，不占查看页篇幅。仅修改 `enterprise-mvp.tsx` 的详情展示，原企业与用户页面和企业资源有效期保持原规则。

## 历史阶段：企业与用户选定与旧版清理（2026-09-09）

2026-09-09企业与用户定稿：选定原“企业与用户2”，正式名称为“企业与用户”，唯一入口 `?view=enterprise`。旧 `enterprise2`、`enterprise3`、`enterprise4`、`enterprise2Detail`、`memberDetail`、`permissions`、`quota` 地址归一到正式页；旧版组件和比较页签已清理。清理前双版本已提交并推送 GitHub（`f41aa38`），可通过该提交回溯。

- 使用“移除用户”替代停用/恢复账户。有权限时可移除正常、待接受、已过期用户；不能移除自己或 Owner。Owner 管理非 Owner，Admin 仅管理 Developer。
- 确认后从用户与配额、搜索、筛选、总数中移除并释放占用席位；待接受邀请同时失效。取消、关闭或校验失败不改变数据。
- 底层保留稳定用户身份、历史 Key 元数据、费用、用量与归属。原企业 Key 永久失效，不能通过启用或重新邀请恢复；个人身份与个人 Key 不受影响。
- 同一手机号可通过“邀请用户”重新加入：生成新的成员关系版本和待接受记录，重新设置角色、模型和并发，接受邀请后生效。旧邀请或旧弹窗不得修改新关系；不提供直接恢复入口。
- 企业总席位为50；可邀请=max(0,50−已加入−待接受)。无待接受且已加入7位时显示43 / 50席；待接受数量为0时隐藏其文案及分隔点。上限同时用于展示和邀请提交校验。
- 用户详情保留企业 API Key 的只读名称/掩码、状态、最近调用三列，不展示有效期或完整密钥；只展示当前已授权模型，零授权给空状态。未授权模型仅在邀请/编辑中供选择，摘要仍展示已授权数/企业模型总数。


验证：成员与费用测试31项、用量数据测试8项、页面契约56项通过；TypeScript、变更文件ESLint及Next生产构建通过。浏览器确认旧enterprise2自动归一、三个页签、43/50席与详情单授权模型、三列Key。
