# v3 Demo PM 评测记录（2026-09-02）

## 结论

本轮以“顶部 Project 上下文是否贯穿客户侧链路，以及配额控制主体是否唯一”为主线，检查项目、凭证、配额、费用、用量、请求日志和服务质量。原型层核心链路可演示；此前存在的项目上下文冲突、静态数据串项目和配额层级混淆问题已修复。配额页现在明确 Project 是配置主体，服务账号是继承层，API Key 是调用凭证。

## 已修复

| 问题 | 证据/影响 | 处理 |
| --- | --- | --- |
| 全部项目下无法创建 API Key | 点击创建只出现“请先在顶部选择一个项目”的阻断提示 | 全部项目时在弹窗选择可管理项目；具体项目时只读显示归属项目 |
| Key 弹窗没有随新建项目更新 | 新项目无法成为后续 Key 的归属目标 | 弹窗使用共享 `workspaceProjects`，新建项目立即进入可选列表 |
| 订单与权益固定展示客服播报订单 | 切换到内部评测/新项目仍会看到客服播报订单 | 按 `projectContext` 过滤；无订单项目显示空状态 |
| 新项目 API Keys 为空白表格 | 用户无法判断是加载失败还是尚未创建 | 增加“当前项目暂无 API Key”空状态和创建入口 |
| 音色授权固定展示项目范围 | 项目切换后范围表达不准确 | 全局授权与项目授权分开过滤；无项目授权时显示空状态 |
| 配额页面存在不可达的旧静态分支 | 后续维护可能误改到旧逻辑 | 删除旧分支，统一使用 `QuotaView` |
| 请求日志筛选后右侧仍保留上一条证据 | 空结果时会产生“筛选结果”和详情不一致的错觉 | 详情只从当前筛选结果选择；无结果显示“暂无请求证据” |
| 新项目服务质量回退到旧项目静态指标 | 新建项目会看到不属于它的 ASR 可用性、时延和评测数据 | 新/未知项目使用独立空状态页；只有已有指标快照的项目展示质量看板 |
| 配额控制层级混乱 | 原表格同时出现项目、服务账号、API Key，且没有继承关系 | 改为“归属 Project / 策略对象 / 继承关系 / 指标 / 当前-上限 / 来源”；服务账号默认继承，Key 只作凭证 |
| 配额申请缺少上下文 | 全部项目下无法确认申请针对哪个合同项目 | 新增 Project 选择和站内申请弹窗，Owner/Admin 提交后通知；Finance/Developer/Viewer 只读 |

## 有意保留的边界

- 费用余额、账期权益和商务订单是 Workspace/商务同步结果，允许在费用概览中保持账户级聚合；项目级费用与用量在“用量明细”中查看。
- 服务质量中的离线模型评测是服务/模型快照，不等同于某个成员的个人指标；线上请求、项目筛选和服务事件仍按 Project 过滤。
- “全部项目”只用于聚合查询；Key、配额配置等写入动作必须落到具体 Project。

## 仍需后端才能完成

- 真实成员邀请、登录/MFA、RBAC 持久化和审计写入。
- API Key 的安全生成、只展示一次、轮换窗口与服务端吊销。
- 网关日志、MeterEvent、计费规则和服务质量指标的真实数据接入。
- 商务订单/权益同步和额度申请的真实工单链路。
- 服务账号级严格覆盖策略的后端校验与网关执行；当前 Demo 仅模拟 Project 基线和继承后的有效值。
