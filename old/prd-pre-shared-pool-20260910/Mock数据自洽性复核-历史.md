## 1. 发现与修正

| 问题 | 修正 |
|---|---|
| 按所有模型生成每个成员用量，导致无ASR授权的成员仍产生ASR费用；管理员与Developer看到同一用户的合计不同 | `mvp-fixtures.ts`冻结历史授权，只生成授权生效期间的用量；费用2、用量9与凭证2统一读取这一份数据 |
| 样例Key和成员在8月停用，9月仍有新增用量；最近调用沿用旧静态文本 | 按固定停用时间截断样例历史；最近调用取该Key最后一个有用量的日期，统一为该日20:00；不用停用时间替代最近调用 |
| 独立编造企业与成员峰值，出现企业峰值大于所有成员峰值之和，以及所有成员同一时刻的用量大于企业峰值 | 按同一时刻的成员并发占用生成企业总量，再分别取峰值；保持峰值时上限与可编辑当前上限分离 |
| 复用旧版Key元数据，所有成员使用相同掩码，还保留轮换版本；未调用Key却有积分文本 | MVP样例掩码按成员和Key唯一，统一一次创建版本；积分与最近调用取实际样例历史；新建、未使用Key保持零用量 |
| 企业6月已有成员和音色权益，认证却写8月完成 | 统一企业主体，认证日修正为2026-06-18，账单预览复用相同主体；信用代码掩码保留18位长度 |
| 当前无授权模型仍显示“当前授权上限1路”；余额摘要缺少截至时间 | 未授权处不显示占位上限；余额明确截至2026-09-08 21:00 |

## 3. 历史与权限规则

- 本人对账可查询当前可用模型和本人历史授权期间已有用量的模型；收回调用授权不改写、隐去已产生的本人账期记录，也不会恢复调用权限。
- 演示操作发生在固定计量快照之后：新建Key没有历史，停用成员/Key保留已计量消耗。新邀请不自动获得Key、历史用量或历史并发峰值。
- 样例迁移仅修正内置Key元数据，保留已有邀请、授权修改、停用状态与用户创建的Key；不重置旧版数据。
- 金额和积分按“日×模型×用户×Key”的样例计量行舍入到分，再相加。总行以这些账务行求和，不对已汇总值重复换算；不是生产价格或合同口径。
