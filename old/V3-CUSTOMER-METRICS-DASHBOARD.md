# V3 企业客户指标看板规范

## 1. 目标与边界

看板面向已签约企业客户，用于回答三个问题：服务是否按合同稳定提供、模型实际表现如何、账期费用由哪些调用构成。它不是内部运营看板，也不提供线上验收、对账确认或争议处理动作。

统计主链路为：

`Workspace → Project → API Key → request_id → MeterEvent / 服务质量证据`

企业成员只决定谁能查看或管理上述对象，不作为调用量、费用或模型质量的归属维度。

## 2. 服务质量指标框架

### 2.1 合同履约层

| 指标 | 精确定义 | 数据源 | 展示 | 目标/阈值 |
|---|---|---|---|---|
| 月度服务可用性 | `(账期总分钟－服务方不可用分钟)÷账期总分钟` | API 网关、超时窗口、责任归因事件 | KPI + 目标线趋势 | 合同目标 ≥ 99% |
| 服务方不可用分钟 | 客户正常请求中，因服务方 5xx 或超时形成的连续不可用窗口累计 | 责任归因事件 | 公式与事件表 | 进入可用性公式 |
| 重大故障首次响应 | 重大故障发现至首次响应时间 | 服务事件时间线 | SLA 阶段表 | ≤ 15 分钟 |
| 初步判断用时 | 重大故障发现至提供初步判断 | 服务事件时间线 | SLA 阶段表 | ≤ 30 分钟 |
| 恢复/替代方案用时 | 重大故障发现至恢复或提供认可替代方案 | 服务事件时间线 | SLA 阶段表 | ≤ 120 分钟 |
| 排除项 | 客户 4xx/429、维护、第三方、不可抗力等不计入项 | 网关、维护日历、责任分类 | 单独列表 | 不得静默剔除 |

### 2.2 TTS 模型观测层

| 指标 | 定义 | 类型 |
|---|---|---|
| 请求成功率 | 有效请求中正常完成的请求占比 | 线上运行 |
| 首包音频时延 TTFA | 请求接收至首个可播放音频包，展示 P50/P95/P99 | 线上运行 |
| 端到端时延 | 请求接收至合成完成，展示 P50/P95/P99 | 线上运行 |
| 实时率 RTF | 合成耗时÷生成音频时长，越低越好 | 线上运行 |
| 完整生成率 | 正常输出结束标识且音频可解码的请求占比 | 线上运行 |
| MOS | 固定评测集上的主观自然度评分，展示样本量和版本 | 离线评测 |
| 音色相似度 | 克隆音色与参考音色的向量相似度 | 离线评测 |
| 可懂度 CER | 合成音频回识别后的字符错误率 | 离线评测 |
| 时长控制误差 | 目标时长与输出时长的相对误差 | 离线评测 |

### 2.3 ASR 模型观测层

| 指标 | 定义 | 类型 |
|---|---|---|
| 请求成功率 | 有效请求中正常返回识别结果的请求占比 | 线上运行 |
| 首个中间结果时延 | 音频开始上传至首个稳定中间文本 | 线上运行 |
| 最终结果时延 | 音频结束至最终文本返回 | 线上运行 |
| 实时率 RTF | 处理耗时÷音频时长 | 线上运行 |
| 中文 CER | 中文固定评测集字符编辑距离÷参考字符数 | 离线评测 |
| 英文 WER | 英文固定评测集词编辑距离÷参考词数 | 离线评测 |
| 热词召回率 | 参考热词中正确识别数量÷热词总数 | 离线评测 |
| 说话人分离 DER | 错分、漏分和虚警时长÷总说话时长 | 离线评测 |
| 标点 F1 | 标点预测的 Precision/Recall 调和平均 | 离线评测 |

离线评测指标必须同时显示评测集版本、样本规模、语言/场景分布和更新时间；不得把演示数据标成合同承诺。

## 3. 用量与对账指标框架

| 指标 | 精确定义 | 数据源 | 客户动作 |
|---|---|---|---|
| 网关有效请求 | 鉴权通过且进入模型处理的请求；客户 4xx/429 单列 | API 网关 | 下钻请求日志 |
| 计费请求 | 按计量规则产生有效 MeterEvent 的请求 | MeterEvent | 下钻 request_id |
| 计费字符/音频时长 | TTS 按 Unicode 字符；ASR 按合同定义的音频时长 | MeterEvent | 按 Project/API Key/模型拆分 |
| 排除用量 | 鉴权失败、限流、服务方失败、重复事件等不计费数量 | 网关与计量校验 | 查看排除原因 |
| 预计 API 费 | 各计量单位 × 对应 PriceBook 单价 | MeterEvent + PriceBook | 核对费用构成 |
| 并发扩容费 | 生效扩容路数 × 月单价 × 生效周期规则 | Entitlement + PriceBook | 查看权益依据 |
| 对账差异率 | `|网关应计费事件－有效 MeterEvent|÷网关应计费事件` | 对账作业 | 查看缺失/重复/冲正 |
| 数据完整性 | 完整、生成中、部分数据、已更正 | 对账快照 | 判断当前数字能否使用 |

## 4. 布局与联动

服务质量页筛选顺序为：统计周期、项目、服务/模型版本、数据状态。合同履约、线上运行、离线评测、事件和 request_id 使用同一筛选范围。

用量页筛选顺序为：账期、项目、服务类型、归因维度、数据状态。默认先按项目查看，再下钻API Key 和模型。所有 KPI、趋势、费用汇总、对账结果和明细表必须来自同一组 mock 数据状态。

## 5. 演示数据声明

所有指标为可交互的确定性模拟数据。界面显示数据来源、规则版本、评测集版本、更新时间和统计范围，并持续声明最终费用以商务结算单为准、合同履约数据仅供客户查询核查。
