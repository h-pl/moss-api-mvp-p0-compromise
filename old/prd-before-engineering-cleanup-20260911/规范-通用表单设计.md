# 通用表单与列表规范（MVP-P0）

同步基线：2026-09-09 [研发主 PRD](./PRD-管理和组织模块.md)与[飞书研发文档](https://acnc6zeentra.feishu.cn/wiki/GfJQwQLMFiabOOktdUNcaAxsnRd)。本文细化对应章节的研发要求，截图为线上演示快照；生产数据及权限以服务端为准。

对应主 PRD 7.2、7.3、7.6；视觉值见[设计规范](./DESIGN.md)。

## 列表筛选

筛选输入/下拉字号12px、高38px，间距12px；原生select接受平台弹出层。搜索框复合容器只显示一层 #596168 焦点描边，内部input不重复。清空搜索保留焦点；重置仅非默认态显示、无下划线、紧接最后一个筛选项。成员、费用和用量空态内提供同名“重置筛选”；API密钥当前仅在筛选栏提供，差异见主PRD文末Q-01。筛选及pageSize改变回第一页。

分页由 `app/v3/pagination.tsx` 统一，5/10/20，默认5。区间/总量文本、上一页/下一页、首末及空态禁用完全一致；列表总数、筛选结果、账务筛选全量合计不混淆。无结果0–0且页码1/1，任何数据变化不出现越界页。

## 创建和编辑

标签必须关联字段，搜索可用sr-only。API Key名称1–50字，手机号有效11位。邀请/编辑统一使用两列模型卡：首行“模型名 · 企业并发上限 X 路”，次行“成员上限”输入和单位“路”。勾选后默认留空，提示“不限制”；取消勾选清空并禁用，保存为未授权。邀请至少选择一个模型，编辑可取消全部。填写时只允许1至企业上限的整数，无变化禁用保存。超限仅使企业上限文字与输入边框同色标红，不新增错误行或改变卡片高度；不显示“选填”“最多N路”或顶部解释文案。

字段为空、无效或无改动时提交按钮 #9b9b9b 灰色禁用；可提交时近黑。必要信息不足不发送请求。保存失败保留字段值、定位错误并以role=alert呈现；成功后提交状态才关闭。

## 确认及成功态

启停Key/移除用户使用同一alertdialog结构：对象、影响、取消和确认。取消默认聚焦；停用/移除为危险色，启用近黑。取消不改数据；错误留在确认层。创建Key成功立即入列，关闭成功态不得撤销；完整Secret一次展示，复制按真实剪贴板结果反馈。

## 焦点和弹层

统一ModalSurface：顶层dialog、背景不可操作、Escape关闭、关闭后回到触发器，关闭热区至少44px。长内容只保留一个内部滚动区。表单首字段获得初始焦点，确认层取消获得初始焦点。页签使用Tab进入选中项、左右方向键/Home/End切换。

## 窄屏

输入、下拉、每页选择器及按钮以完整控件换行；邀请与编辑模型卡宽屏为两列，620px及以下为单列，按钮不可竖排，正文可滚动但整页不得横向溢出。

## 页面应用

| 页面 | 场景 |
|---|---|
| API 密钥 | 搜索/状态、创建、启停、共享分页 |
| 企业与用户 | 搜索/角色/状态/接近上限、邀请/编辑、详情、移除、共享分页 |
| 费用概览 | 账期/模型/用户、重置、共享分页、账单预览 |
| 用量明细 | 账期/模型/用户/Key/窗口、重置、共享分页、授权账期导出 |

## 服务端校验与验收

Owner由模思运营人员根据销售订单在后台配置，成员邀请表单仅提供操作者允许配置的Admin/Developer角色。Owner可配置Admin和Developer，Admin仍可配置Developer的模型授权与并发。

前端校验用于及时反馈。生产端重验角色、归属、成员关系版本、重复手机号、席位及Key额度。成员模型上限可留空；填写时为1至企业模型上限的整数，不校验成员上限之和。Owner可编辑本人模型授权及上限，不能修改手机号或角色；Admin仅操作Developer。版本冲突保留输入并要求刷新。

重复提交期间禁用操作；网络失败保留草稿，版本冲突显示刷新指引，身份切换清空草稿与旧响应。按主 PRD AC-03–06、AC-13、AC-14验收字段边界、失败状态、取消、焦点和分页。
