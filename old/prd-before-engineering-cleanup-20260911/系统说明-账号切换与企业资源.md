# 系统说明：企业上下文与资源（MVP-P0）

同步基线：2026-09-09 [研发主 PRD](./PRD-管理和组织模块.md)与[飞书研发文档](https://acnc6zeentra.feishu.cn/wiki/GfJQwQLMFiabOOktdUNcaAxsnRd)。本文细化对应章节的研发要求，截图为线上演示快照；生产数据及权限以服务端为准。

对应主 PRD 7.1、7.7、7.8、7.10；计量细则见[费用中心 PRD](./PRD-费用中心.md)。

## 1. 权威上下文

企业Owner由模思运营人员根据销售订单在后台配置，控制台读取该权威成员关系。Owner管理Admin/Developer的模型授权和并发上限；Admin继续保留对Developer的配置权限。演示角色参数只用于原型切换，不代替运营后台授予Owner资格。

用户、企业、成员关系、角色、授权模型和并发策略由服务端确定。前端参数只能缩小允许范围，不能越权指定其他企业或用户。企业演示角色为Owner/Admin/Developer；当前演示Admin优先使用正常在册的王开发；若已移除则选择其他正常Admin，不恢复已移除关系；无正常Admin时显示个人身份。正常Admin为企业成员，可访问企业四页并配置Developer的模型授权和并发上限。日常访问从进入控制台开始；有正常企业成员关系的用户按需点击左下角用户信息卡片，在“切换身份”中选择“企业”或“个人”；identity=personal进入 C 端个人页，隐藏企业数据；右上角演示角色切换始终保留。无企业账号只能进入个人页。

`resolveMvpView` 统一处理初始化、页面切换、历史记录恢复和角色变更。仅允许 keys/billing3/usage3/enterprise；Developer 访问 billing3 回到 usage3，访问企业管理回到 keys。身份或角色变化清空搜索、筛选、页码、草稿、弹窗、下钻参数、旧请求结果和下载上下文。生产需隔离会话与缓存，并阻止旧在途响应覆盖新身份。

## 2. 成员状态与原子写入

未加入 → 待接受 → 正常；邀请从服务端创建成功起7天（7×24小时）有效，到期未接受则链接失效、状态转为已过期并释放席位；接受成功后成员资格不随原邀请到期失效。正常、待接受或过期成员可移除。移除是关系归档，不删除账号和历史账本。重新邀请复用稳定用户身份并增加关系版本，授权重新配置。

`prepareMemberChange` 校验当前操作者、对象、角色范围、重复手机号、席位及模型并发；`applyMemberChange` 原子生成成员与企业 Key 快照。只有成功快照提交后界面才更新。生产写入须校验关系版本，旧邀请或表单不能重放到新关系。

总席位50，正常成员和有效待接受邀请占用席位，过期释放席位。同一企业同模型共享并发池，成员上限不预留资源且总和可超过企业上限；留空表示不单独限制，生效上限随企业上限。填写时为1至企业模型上限的整数。邀请只占席位，实际请求占用由网关原子计数并在结束时幂等释放。

短信使用7天有效的服务端邀请凭证，点击时新建短期SSO状态并携带可验证的邀请上下文。Mossland登录预填受邀手机号；新用户完成验证码、协议同意及登录后自动注册，已有用户使用受邀账号登录，已有会话先核对手机号。SSO回跳时账号服务重验手机号、邀请期限/撤销/关系版本并幂等接受，待接受席位转为正常成员席位，不重复占用；保存的授权与可空上限生效，并发不预留；成功后刷新身份关系，企业选项出现在左下角用户卡片，按需切换。短信发送失败、SSO超时、错误账号和失效邀请分别处理，不能仅凭登录成功显示企业权限。完整文案及验收见主PRD7.6.4。

## 3. Key状态机

创建成功 → 有效；有效 → 普通停用；普通停用 → 有效需重新校验本人、成员状态和模型授权。成员移除 → 原企业 Key 永久失效，重新邀请不能恢复历史 Key。

Key 绑定稳定用户与企业；个人Key、他人Key不受当前成员移除影响。`validateMvpKey` 校验归属、50个现存Key上限和动作前态。生产由服务端签发Secret和保证幂等，网关使用权威状态，成功态不能通过关闭弹窗撤销。

## 4. 资源与计量

企业合同六模型集中在enterprise-resource-data.ts。Owner首次默认授权全部企业模型，成员上限为null，继承企业上限；本人可编辑授权和可选上限，显式值保留，手机号及角色只读，不能移除本人。Admin仅管理Developer，不能编辑本人或Owner。列表、详情及API密钥资源区统一展示峰值/生效上限；Owner默认两模型68/80、50/60接近上限，无专属继承说明。 历史峰值不改写，80%/100%分类由capacityLimitState统一。

实际计费规则由模思运营根据销售订单在后台配置，控制台从服务端获取企业、模型及生效时间对应的规则版本；原型费率和积分换算率仅供参考。历史账本保留计费时的规则版本，不随当前配置变化重新计价。

账本按稳定模型/用户/Key标识归因，成员生命周期不重算历史费用。积分余额是独立权益快照，不通过本月消耗倒算。逐条计量按积分分/金额分取整后汇总，TTS字符、ASR十分之一秒；显示小时不得反算账务。

## 5. 查询、打印和导出

Owner/Admin 可查企业全量，Developer 仅本人可查询模型范围。用量筛选用户改变重置Key；跨页下钻携带账期/模型/用户并重新鉴权。打印按完整企业账期到模型，CSV按完整授权账期到Key，临时筛选与分页不能扩大或缩小既定导出范围。

## 6. 存储及后端边界

四页通过mvp-storage.ts共用moss-api-shared-enterprise-demo-v2。首次迁移合并原正式页与选定共享页数据，同记录以选定共享页配置为准，保留原页独有成员、邀请和Key，永久失效Key不恢复。显式成员上限保留，缺失Owner配置初始化为null；重置确认后清除新键和两旧键，避免旧数据重新导入。生产仍须服务端鉴权、幂等及真实数据接入。

前端原型不具备真实登录、短信投递、邀请接受、生产签发Key、网关撤权或账务清结算能力。生产必须补充服务端鉴权、访问隔离、请求幂等、配置版本、错误恢复、可信快照、下载权限和可信业务与安全记录。相关资源权益由服务端校验。

个人页采用[现有 C 端](https://platform.mosi.cn/)的信息架构，服务在新窗口打开并使用个人登录；个人与企业数据分别维护。

## 7. 接口交接与失败语义

生产能力按身份上下文、Key管理、成员管理、资源快照、费用/用量、必要业务记录划分，字段及权限要求见主 PRD 7.10。当前组件函数不是已提供的HTTP接口。

Key数量、席位与每模型分配总和原子校验，写请求具备幂等及当前版本检查；成功状态只在服务端提交后产生。网络失败保留输入，版本冲突提示刷新；成员关系失效时撤销旧上下文访问。停用Key与移除成员至少对后续新调用生效，进行中调用策略由服务端明确。

联调验证邀请7天有效期、截止时刻拒绝接受以及席位和额度释放；另需确定会话与敏感操作校验、数据延迟和保留期限、CSV容量与超时、价格舍入与更正规则。生产验收依照主 PRD AC-01–16，附真实接口与状态撤销证据。
