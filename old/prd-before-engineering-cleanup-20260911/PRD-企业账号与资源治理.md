# 企业账号与资源治理 PRD（MVP-P0）

同步基线：2026-09-09 [研发主 PRD](./PRD-管理和组织模块.md)与[飞书研发文档](https://acnc6zeentra.feishu.cn/wiki/GfJQwQLMFiabOOktdUNcaAxsnRd)。本文细化对应章节的研发要求，截图为线上演示快照；生产数据及权限以服务端为准。

对应主 PRD 7.1、7.3、7.6–7.7、7.10；覆盖本人 Key、成员关系、资源。

## 1. 账号、身份与权限

企业Owner由模思运营人员根据销售订单在后台配置。Owner为成员配置模型授权和并发上限；Admin保留对Developer的配置权限。成员本人管理企业API Key。Owner身份由后台关系授予，企业控制台的成员邀请和演示角色选择不能创建Owner身份。

- 用户为稳定账号；企业成员关系承载角色、模型授权和各模型并发限制。企业 Key 绑定企业及用户，多个 Key 共享本人模型策略；调用使用企业资源并记入企业费用。
- 有正常企业成员关系才可点击左下角用户信息卡片，在“切换身份”中选择“企业”或“个人”；个人身份进入 C 端个人页，隐藏企业导航和数据。无企业账号只展示个人信息，不提供身份切换。企业操作不修改个人账号及 Key。
- Owner 管理 Admin/Developer，Admin 只管理 Developer；不能移除Owner或由他人修改Owner；Owner可编辑本人并发额度，角色与模型授权不变。Developer 仅可管理本人企业 Key 并查看本人用量，不能访问企业管理和费用概览。
- Owner首次默认授权全部企业模型，成员上限为null，继承企业上限；本人可编辑授权和可选上限，显式值保留，手机号及角色只读，不能移除本人。Admin仅管理Developer，不能编辑本人或Owner。列表、详情及API密钥资源区统一展示峰值/生效上限；Owner默认两模型68/80、50/60接近上限，无专属继承说明。 界面不是安全边界，服务端重验全部归属及权限。

## 2. 企业资源与模型授权

企业资源池依次展示企业积分余量、已开通模型、可邀请席位；总席位 50，正常和待接受占用，已移除及过期邀请不占用。辅助文案始终保留已加入数量，仅待接受大于0时追加占位数量及分隔点。余额和有效期为独立快照。

按需展开全部合同模型，仅两列：已开通模型、近 24h 并发峰值 / 企业并发上限。API 密钥页以本人范围展示三列并保留本月已用积分。两处资源头均不展示额外只读角标。

用户与配额列表的并发表头为“近 24h 并发峰值 / 成员并发上限”；每行展示所示模型的成员峰值与当前成员上限。

近24h峰值与当前同范围上限比较：不足80%中性，80%至不足100%接近上限，100%起已达上限；两类互斥，零数量隐藏。未知、未覆盖、无效峰值不误判为0或充足。调整上限只改变分母、状态和筛选，不回写历史峰值。

## 3. 成员邀请与编辑

手机号为中国大陆11位有效格式，默认Developer。邀请/编辑统一使用两列模型卡：首行“模型名 · 企业并发上限 X 路”，次行“成员上限”输入和单位“路”。勾选后默认留空，提示“不限制”；取消勾选清空并禁用，保存为未授权。邀请至少选择一个模型，编辑可取消全部。填写时只允许1至企业上限的整数，无变化禁用保存。超限仅使企业上限文字与输入边框同色标红，不新增错误行或改变卡片高度；不显示“选填”“最多N路”或顶部解释文案。 编辑回填，手机号只读。

正常及待接受用户可编辑；过期邀请仍可移除后重新邀请。重复正常或待接受成员、席位用尽、角色越权、无模型和并发越界均拒绝并保留输入。邀请链接从创建成功起7天（7×24小时）有效；到期未接受则链接失效、状态为已过期并释放席位。创建有效待接受邀请仅占用席位；接受后转正常成员席位且不重复占用，授权及可空上限生效，链接不可重复使用，成员资格不随邀请到期失效；修改待接受配置不延长期限。过期后移除记录再重新邀请，新链接重新计时，旧链接保持失效。当前演示仅生成待接受状态，真实链接投递、到期与接受流程需接入后端。

邀请短信签名为【模思智能】，正文模板和完整登录分支见主PRD7.6.4。有效邀请入口预填受邀手机号；未注册用户完成验证码验证、协议同意并登录后自动注册，已注册用户使用对应账号登录，已登录用户直接校验。服务端必须比对已验证手机号与受邀手机号，回跳时重验期限及版本并幂等接受；正常成员关系落库后刷新企业选项，用户通过左下角卡片切换。错误账号不加入，邀请过期/撤销或旧关系链接不恢复权限；已接受且仍正常的同一邀请重复访问不重复占位。

## 4. 移除与重新邀请

确认移除后，从主列表、搜索、计数中移除，释放席位并使原企业Key永久失效；在途实际请求结束或确认终止后才释放占用，不能提前清零。取消不改状态，个人账号/Key及历史账本不变。

同一手机号重新邀请复用稳定账务身份，产生新的成员关系及授权；接受后需新建 Key，历史 Key 不得重新启用。服务端应原子更新成员和 Key，并使网关校验失效；不能由浏览器本地状态代替。

用户详情只展示已授权模型及只读企业 Key 三列：名称/掩码、状态、最近调用；详情内Key展示全部记录，不使用四张主列表分页；详情可进入编辑与移除确认，取消编辑返回列表。动作权限与列表一致。

## 5. API 密钥

仅管理本人企业 Key；Owner/Admin 也不能代看明文或操作他人 Key。创建前要求成员正常、至少一个授权模型、现存 Key 少于50个（普通停用仍占用，永久失效历史 Key 不占用）。名称去首尾空白后为1–50字。

创建成功立即入列，完整 Secret 只在该成功态展示一次，关闭不撤销；复制成功或失败有反馈，不改变状态。生产 Secret 不进入列表、日志、埋点或持久缓存。

有效 Key 可停用；普通停用 Key 只有本人账号正常且有模型授权时可启用；成员移除造成的永久失效不可启用。二次确认说明对象和影响，取消默认聚焦；失败保持弹窗并展示错误，成功才关闭。停用行中性弱化，启用动作保持可见。

## 6. 费用与记录

费用按稳定企业/用户/Key身份归因，不按名称合并；移除或再邀请不回写账本。费用打印和导出见[费用中心 PRD](./PRD-费用中心.md)。服务端保留必要业务和安全记录。

## 7. 统一交互与生产边界

搜索、重置、5/10/20分页、状态颜色、弹窗焦点遵循[UX 契约](./UX-CONTRACT.md)。密钥与成员使用同一演示存储 `moss-api-shared-enterprise-demo-v2`，刷新保留；生产鉴权、邀请接受、网关撤权、幂等、授权下载与必要业务记录均需服务端接入验收。

右上角演示角色切换在企业和个人身份下始终保留，不受企业账号资格影响；角色不等于企业成员关系，企业账号资格以当前成员状态为准。

个人页采用[现有 C 端](https://platform.mosi.cn/)的信息架构，服务链接在新窗口打开，使用个人登录。企业与个人的数据、Key 和余额分别归属各自上下文。

## 8. 服务端契约与验收

成员读写包含稳定用户 ID、企业 ID、成员关系版本、角色、状态、模型授权、各模型上限及邀请 created_at、expires_at（创建起7天）。创建邀请原子校验手机号与席位；移除同时撤销访问、待接受邀请和原企业 Key。旧邀请、旧表单、旧请求不能应用于新的成员关系。以服务端当前时间早于expires_at且邀请待接受为有效条件，受邀人须验证绑定手机号；到期即时拒绝接受且不再计入席位，不因状态更新延迟继续占位。

资源快照至少包含 scope、model、window_start/end、peak、peak_at、current_limit、coverage、data_as_of。企业峰值取同一时刻全员占用总数的近24h最大值；成员峰值取本人所有企业 Key 的同模型占用最大值。相同峰值取最近发生时间，各成员配置上限之和可以超过企业上限；调用按实际占用同时满足两层限制，结束后幂等释放实际占用。

用户列表“接近上限 N”按全部正常成员去重，任一授权模型达到80%及以上即计入，包含已达上限，不受其他筛选影响；点击后与其他筛选取交集。无覆盖、未授权、无效数据及非正常成员不计入。

按主 PRD AC-02–08、AC-15 验收身份资格、Key额度、成员重邀、容量边界和个人服务入口。补充验证编辑无变化禁用、并发写入时不超卖席位及模型额度、移除失败保留原状态。


## 7. 共享并发与成员上限

并发按企业×模型独立计数，表示同时处理的请求数。设企业上限为E，成员上限为Lᵢ、当前实际占用为Cᵢ，则企业实际占用C=ΣCᵢ≤E；配置Lᵢ时还须满足Cᵢ≤Lᵢ。成员上限为null时不单独限制，仍受E约束。成员配置不预留资源，不要求ΣLᵢ≤E，也不承诺任何成员独占或保底并发。不同企业及不同模型相互隔离。

| 场景 | 规则与验收要求 |
|---|---|
| 共享与调用 | 正常成员获授模型后可使用该模型的共享池。同一成员的多个企业API Key共用成员计数，所有成员共用企业计数。成员上限仅约束本人；空闲资源可供其他有权限的成员使用，总实际占用不能超过企业上限。 |
| Owner默认与编辑 | Owner首次授权所有企业已开通模型，上限默认null并继承企业上限。本人行或详情可编辑模型授权和可选上限；显式保存值保留，不被默认值覆盖。手机号及Owner角色只读，不允许移除本人。取消模型授权不影响企业管理权限和历史查询。Admin仅可配置Developer，不能编辑Owner或本人。 |
| 新增邀请 | 默认Developer、未选模型；勾选后上限留空即不单独限制，填写时只能是1至企业模型上限的整数。至少选一个模型；创建成功仅占用席位，保存授权和上限，不预留并发。短信重试不重复占席位。 |
| 编辑成员或邀请 | 回填显式值；null显示空白及“不限制”提示。保存重新校验权限、成员/配置版本及每项企业上限，不校验成员上限之和；任一项无效时整笔不提交。无变化禁用保存；编辑允许取消全部模型，取消后不能调用对应模型。 |
| 接受、过期与移除 | 接受后授权及上限生效，席位不重复计入。过期或撤销释放席位，成员移除撤销访问并永久失效原企业Key；没有配置额度可供回收。重新邀请重新校验权限与席位，不恢复旧Key；旧请求不能绑定新成员关系。 |
| 请求占用与释放 | 生产网关按企业、成员、模型及成员关系版本原子校验并增加实际占用，避免多个Key并行请求超限。正常结束、失败、取消、超时均须幂等释放占用，异常中断需回收机制；重复结束不得重复扣减。原型未接入真实请求计数。 |
| 策略变更与在途请求 | 调低上限、取消授权或移除后，后续请求按新策略判断；在途请求仍计入实际占用，直到结束或确认终止后释放。具体终止策略见Q-05。企业缩容不改历史配置值和峰值，当前生效上限取min(企业上限,显式成员上限)，占用未降到新上限以内时不再接纳新请求。 |
| 企业扩容与展示 | 企业上限由模思运营根据销售订单配置。成员上限null随企业上限生效；显式值保持不变。列表、详情、API密钥资源区统一展示峰值/生效上限；不限制时分母显示企业上限数字，不增加Owner专属说明。 |
| 卡片和数据契约 | 宽屏两列、620px及以下一列。首行为勾选框、模型名、“· 企业并发上限 X 路”和TTS/ASR；次行为“成员上限”、输入框与“路”，不显示“选填”、顶部说明或“最多N路”。已选且留空提交enabled=true、concurrency=null；填写正整数提交该值；取消勾选输入置空禁用，提交enabled=false、concurrency=0，重新勾选仍留空。超企业上限仅将上限文字和输入边框以#b8323a标红，禁用保存，不新增错误行或改变卡片高度；其他非法数字仅输入框标红，读屏错误通过aria-describedby关联。 |

示例：企业某模型上限100路，A设置60路、B设置80路、C留空，三人共享100路。A正在使用10路时，企业还可接纳90路，B本人最多80路；若A和B合计已用100路，C即使未单独设限也不能继续增加请求。这里不为任何成员预留容量。

专项验收：多个成员上限总和超过企业上限仍可保存；留空、整数1、恰好企业上限可提交，0/负数/小数/超过企业上限被拒；取消授权与不限制明确区分。验证Owner默认继承及显式覆盖、Admin管理范围、旧配置迁移与永久失效Key不恢复。生产联调补充多Key并发原子计数、跨租户隔离、各种结束路径幂等释放、邀请不占并发以及缩容/撤权期间在途计数不提前清零。
